# Squat Overflow mobile (iOS and Android)

The Squat Overflow extension as a React Native app: break reminders, camera-coached 2-minute routines, XP, levels, challenges, badges and the company leaderboard. UI is built with [React Native Reusables](https://reactnativereusables.com/) on Expo (SDK 56, dev builds).

## How it maps to the extension

| Extension | App |
|---|---|
| Toolbar popup | Home (`app/index.tsx`) |
| Options page | Setup / Settings (`app/setup.tsx`) |
| Break window (`break.html`) | Break screen (`app/break.tsx`) |
| Service worker + `chrome.alarms` | `src/core/engine.ts` + local notifications planned by `src/core/plan.ts` |
| `chrome.storage.local` | AsyncStorage (`src/core/storage.ts`, `src/core/store.ts`) |
| On-device pose: MediaPipe `pose_landmarker_lite.task` in the page + `lib/pose` (rep counting, form, calibration) | The same model file through MediaPipe's native SDK (`modules/squat-pose`) + the same `extension/lib/pose` modules, imported as-is (`src/pose/analysis/index.ts`) |
| Google Calendar freeBusy | The phone's own calendars (`expo-calendar`), busy times only |
| 3D exercise demo (`lib/demo-model.js` on a canvas) | The same figure from the same module, drawn with `react-native-svg` (`src/components/DemoModel.tsx`). Same moves, camera swing, drag to turn and Reduce Motion behaviour; nothing is loaded from the network |
| Blurred preview / 3D characters | Privacy mode blurs the camera (`expo-blur`, `src/pose/privacy.ts`); on Android before 12, which has no real blur, the picture is hidden and only the skeleton shows. Characters come later |

The pose analysis, XP, schedule grid, routine, challenge, badge, leaderboard and i18n logic is **not copied**: the app imports the extension's pure modules from `../extension/lib` (see `src/core/shared.ts` and `metro.config.js`), so both clients score and schedule breaks identically and post comparable numbers to the same leaderboard. Only modules with no `chrome.*` or DOM access at import time can be shared.

### Reminders on a phone

A phone app can't run code at an arbitrary time the way the service worker wakes on an alarm, so reminder times are planned ahead and handed to the OS as local notifications (up to 48 ahead, under iOS's limit of 64). Active hours, workdays and calendar meetings are applied when planning. Every action (Done, Snooze, Skip, Pause, settings) replans.

When the app comes back to the foreground it catches up: a reminder that fired becomes the "due" reminder, and one that was still due when the next one fired counts as a skip, like closing the extension's break window without answering. After more than a day away, the schedule starts fresh with no skips. Leaving a reminder's break with ✕ also counts as a skip; leaving a "Break now" break doesn't.

Not ported: the fullscreen and audible-meeting-tab auto-pause (phones have Focus modes and calendar meetings instead), and "away at fire time" idle detection.

## Run it

Needs Node 20+, Xcode 16.4+ with an iOS simulator, Android Studio with an emulator or device, and CocoaPods.

```bash
cd mobile
npm install
npx expo prebuild          # generates ios/ and android/ (gitignored)
npx expo run:ios           # or: npx expo run:android
```

If `pod install` fails with `Unicode Normalization not appropriate for ASCII-8BIT`, set a UTF-8 locale first: `export LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8`.

### iOS 27 needs the scene life cycle

iOS 27 stops an app built with Xcode 27 (the iOS 27 SDK) at launch if it doesn't use the UIScene life cycle. iOS 26 simulators don't check this, so the crash only shows on an iOS 27 phone. Expo SDK 56's template has no scenes, so `plugins/withSceneLifecycle.js` adds them on every prebuild:

- `Info.plist` gets a `UIApplicationSceneManifest` with one window scene.
- `ios/SquatOverflow/AppDelegate.swift` gets a `SceneDelegate` class. It creates the window, starts React Native in it, and hands incoming links on to the `AppDelegate`. `didFinishLaunching` still builds the React Native factory.

Keep the plugin in `app.json`. When an Expo upgrade's template adopts scenes itself, prebuild stops with an error from the plugin; remove the plugin then.

Simulators and emulators have no front camera. In development builds the break screen then runs a simulated coach (a rep every couple of seconds) so the whole flow can be tried; it says so on screen. Real pose detection needs a physical phone.

## Tests

```bash
cd mobile
npm test            # planner, shared-logic bridge, and extension/lib/pose parity with the Python server's recorded fixtures
npm run typecheck
```

The analysis tests replay landmark sequences through both the Python `Session` (fixtures generated by `scripts/gen_pose_fixtures.py` with the server's venv) and the TypeScript port, and require identical results.

## Layout

```
app/                    screens (expo-router)
components/ui/          React Native Reusables components (added with the reusables CLI)
src/core/               storage, engine, planner, notifications, calendar, sounds, i18n overlay, shared-logic bridge
src/components/         app components (chips, heatmap, challenges, leaderboard, avatars)
src/pose/               camera + skeleton + analysis (TypeScript port of server/analysis)
src/theme/              the extension's 7 themes as Reusables color tokens
modules/squat-pose/     native module: MediaPipe Pose Landmarker on Vision Camera 5 frames (Swift + Kotlin, Nitro)
assets/sounds/memes/    the extension's meme clips as AAC (.m4a), since iOS can't play Ogg
```
